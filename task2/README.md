# MCP Security Gateway

This is an HTTP reverse proxy written in Python with Starlette and httpx that sits between an MCP client and a downstream MCP server, with `mock_server.py` as the downstream for testing. Every request needs an `Authorization: Bearer <token>` header holding an HS256 JWT with `sub`, `exp`, and a `role` of `admin` or `viewer`, and anything missing, expired, badly signed, or with an unknown role gets HTTP 401 before the body is even read. The gateway parses each message as JSON-RPC 2.0, forwards `tools/list` and every other method through unchanged, and checks `tools/call` against the token's role. If `params.name` starts with `admin_` (in any letter case) and the caller isn't an admin, it returns a `-32001 Unauthorized Tool Call` error with the original request id and never contacts the downstream server. Malformed messages get `-32700` or `-32600`, and a `tools/call` without a string tool name gets `-32602`. A few things are blocked on purpose because they could sneak an admin call past the check: duplicate JSON keys, batch arrays (MCP no longer supports batching), and tool names with characters outside the MCP naming rules, like a leading space or a fullwidth "ａｄｍｉｎ". The gateway forwards the message it checked rather than the raw bytes, only passes MCP headers like `Mcp-Session-Id` downstream, never forwards the client's token, streams SSE responses through as they arrive, and returns `502` or `504` if the downstream server is down or slow. To run it, install the requirements with `pip install -r requirements.txt` from this folder (Python 3.10 or newer), set `GATEWAY_JWT_SECRET` to any string of 32+ characters, start `python mock_server.py` and `python gateway.py` in two terminals, make a token with `python mint_token.py viewer`, and send requests to `http://127.0.0.1:8000/mcp`. Run the tests with `python -m pytest -v`. They also run on Windows, macOS, and Linux through GitHub Actions.
